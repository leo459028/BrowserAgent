# BrowserAgent 一般人版說明

最後更新：2026-05-21

這份文件是給非技術背景的人看的。它不會深入程式碼，也不假設你知道什麼是 `API`、`Kafka` 或 `Planner`。如果你只想知道「這個專案拿來做什麼、適合做什麼、不適合做什麼」，看這份就夠了。

## 1. 這個專案的作用

BrowserAgent 是一個讓系統「代替人操作瀏覽器」的基礎平台。你可以把它想成一個受控的瀏覽器助理：它可以開網頁、按照任務步驟操作頁面、截圖、保存網頁內容，最後把結果記錄下來，讓人可以檢查。

它不是單純的自動化腳本，而是比較偏企業使用的雛形平台。重點不是「讓瀏覽器隨便做任何事」，而是讓每個任務都有規則、有審核、有記錄、有產出物，也有錯誤時可以追查的線索。

### v0.4 目前做到什麼

v0.4 的重點是讓瀏覽器任務更容易被檢查和測試：

- 有一個本機 Dashboard 可以建立任務、核准任務、查看狀態。
- 任務會先進入人工核准，不會建立後就立刻執行。
- 系統會把任務拆成瀏覽器步驟，例如開網頁、等待、截圖。
- 如果系統產生的步驟格式不正確，會改用安全的備用步驟。
- 可以看到每個步驟是否有對應到已註冊的能力。
- 任務完成後會保存截圖和 HTML，方便事後檢查。
- 所有重要狀態會留下紀錄，例如建立、核准、執行、完成、失敗。

### v0.5 預計方向

v0.5 會更靠近正式使用環境，重點會放在登入和權限：

- 加入正式使用者登入。
- 不同角色有不同權限，例如建立任務的人、核准任務的人、管理員。
- 核准紀錄會綁定真實使用者，而不是現在的 demo 使用者。
- Dashboard 的人工核准流程會更接近正式作業。

### v1.0 預計方向

v1.0 會朝 production-ready 平台前進，目標是能在更穩定、更大規模的環境中使用：

- 支援更完整的部署方式，例如 Kubernetes。
- Worker 可以擴充數量，處理更多任務。
- 加入更好的重試、排隊、失敗任務處理。
- 強化瀏覽器執行環境的隔離，降低風險。
- 使用更正式的機密管理方式。
- 加入更完整的監控、告警和追蹤。
- 可能加入瀏覽器操作回放，讓人能看任務怎麼跑。

## 2. 應用場景

### 網頁流程檢查

例如公司想定期確認某個網站頁面是否能正常打開、內容是否存在、畫面是否和預期相近。BrowserAgent 可以開頁面、截圖、保存 HTML，讓人之後查看。

### 網站資料留存

有些流程需要保存「當下看到的畫面」作為證據，例如活動頁、公告頁、商品頁、價格頁。BrowserAgent 可以保存截圖和 HTML，並附上時間、任務狀態和檢查結果。

### 內部系統操作測試

在受控環境下，可以用來測試內部系統的簡單流程，例如打開頁面、檢查是否進入正確網域、截圖留存。這比較像 smoke test，不是完整測試平台。

### 需要人工核准的自動化

有些任務不適合一建立就自動執行。BrowserAgent 目前的流程會先進入 `pending_approval`，需要人按下核准才會排隊執行。這適合需要保守控管的瀏覽器自動化。

### 瀏覽器自動化平台的原型

如果你想評估「企業內部能不能做一個有規則、有審核、有紀錄的瀏覽器代理平台」，這個專案可以當作雛形。它已經有任務、審核、執行、產出物、紀錄和 Dashboard。

## 3. 不適合的場景

### 不適合拿來直接上正式生產環境

目前還是 scaffold，不是完整產品。正式環境需要登入、權限、機密管理、監控、告警、部署、擴充和安全隔離都更完整。

### 不適合處理高風險操作

例如轉帳、付款、修改帳戶資料、提交法律文件、刪除重要資料等。這類操作需要更嚴格的權限、逐步確認、審核流程和安全設計。

### 不適合繞過網站規則

這個專案不是用來破解網站、繞過限制、規避驗證或大量抓取資料。它的設計方向是受控、自律、有紀錄的瀏覽器自動化。

### 不適合取代完整 QA 自動化平台

它可以做簡單的瀏覽器任務和 smoke test，但不是完整的測試框架。若要做大量測試案例、細緻斷言、跨瀏覽器矩陣測試，仍需要專門的 QA 工具。

### 不適合處理需要大量人工判斷的任務

如果任務本身需要理解複雜內容、做商業判斷、審核法律風險或判斷圖片語意，目前這個版本不適合直接自動完成。

## 4. 相關特性和限制

### 已有特性

- 有本機 Dashboard 可以建立、核准、查詢和測試任務。
- 有任務狀態流程，例如 `pending_approval`、`queued`、`executing`、`completed`、`failed`。
- 有 allowlist 機制，非允許網域會被擋下。
- 高風險和敏感指令會要求人工核准。
- 任務會留下 audit 紀錄，方便追蹤發生過什麼事。
- 任務完成後會保存 screenshot 和 HTML。
- Artifact 讀取有基本的 tenant 和檔案路徑檢查。
- Planner 輸出會被檢查，不合格時會使用安全 fallback。
- SkillHub 可以記錄能力是否有被解析到，但目前只做 metadata。

### 目前限制

- 尚未有正式登入和角色權限。
- 目前使用固定 demo 使用者。
- Planner 仍是簡單規則，不是外部 LLM。
- SkillHub 目前不執行第三方工具，只記錄解析結果。
- Artifact 目前存在 local filesystem，還沒有真正使用 MinIO/S3。
- Dashboard 是本機測試工具，不是正式營運後台。
- Metrics 是 process-local，不是完整分散式監控。
- Worker retry、DLQ、任務重播、擴充部署都還需要加強。
- 瀏覽器隔離目前是 Docker + Playwright，還不是更強的 sandbox。

### 白話總結

BrowserAgent 現在適合拿來做「受控瀏覽器自動化平台」的原型和測試。它能展示一個任務從建立、核准、執行、截圖、保存結果到留下紀錄的完整流程。

但它還不是可以直接交給公司正式大量使用的產品。v0.4 的價值在於把任務規劃、備用流程、能力解析和 Dashboard 查詢補起來；v0.5 到 v1.0 則會往登入權限、生產部署、安全隔離、監控和更完整營運能力前進。
